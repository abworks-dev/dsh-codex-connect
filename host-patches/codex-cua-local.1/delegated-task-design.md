# Single-task human consent for the local CUA candidate

This is the maintainer-approved local-instance extension, not a general permission service or an upstream release. The next Host identity is `0.2.2-alpha.2.codex-cua-local.2`; local.1 and the published package do not provide this contract. Existing system permissions and saved application grants are unchanged.

The Host's optional `cuaTaskApproval` service is available only with strict native window enforcement. `begin({ parent, child, application, windowId, goal, expiresAt, signal })` validates the exact live runtime root and its owned live child, fixes the target and deadline, and returns a process-local task handle with `id`, `signal`, and an asynchronous `revoke()`/`dispose()`. This registration grants no access. The companion registers before starting the child's model loop and disposes the handle before releasing its desktop lease. No token, caller identity, approval answer, or permission flag is accepted from model tool arguments.

Only the matching child's first `getApp` may acquire native application identity metadata. Before returning a usable handle, the Host asks through the existing root-owned `userQuestions` interaction. The root conversation shows the native application name, process/window identifiers, task text, expiration time, and the limits on allowed operations. Its only actions are **Allow this task** and **Deny**. This is a user-question interaction, separate from `approval/request` and Codex Auto-review. The existing exact-root check is retained; the child is never represented as a root. No persistent or session application permission is copied or written.

The task record binds native application identity and selected handle to the registered child, configured window, and deadline. Every subsequent dispatch checks the live root/child relationship and task signal. The Host admits only `getApp`, strict window `getState`, screenshot, primary unmodified click, scroll, and `setValue`. Indexed actions require the latest native strict-window snapshot. Application menus, global keyboard/text, clipboard, app discovery/launch, other windows, and foreign handles/snapshots are refused. Native strict window ownership remains the final execution boundary.

The root conversation's **Stop** action cancels the parent tool and revokes its task grant; the approval detail explains this control. The Host task handle also exposes revocation for its trusted owner. Denial, cancelled or invalid answers, stale root/child identity, task cancellation, revocation, expiration, provider unload, or task completion abort the grant. Cleanup joins in-flight work before releasing the desktop lease. A cancelled native input is never replayed. No grant survives process restart or can be reused by another child/task. Ordinary non-delegated CUA authorization keeps its existing behavior.

Implementation is limited to the CUA Host runtime/type patch, companion lifecycle, distinctly versioned local compatibility metadata, and synthetic regression/CI coverage. It does not modify the `userQuestions` root guard, native AX implementation, global approval policy, OS settings, or other local instances. There is no new background job system or permission database.

Offline validation must cover genuine root/owned-child admission, forged/stale identities, denial and malformed/late answers, exact prompt scope, no observation/input before approval, target and snapshot substitutions, no writes to the application-permission store, cancellation/revocation/deadline during native work, cleanup, and unchanged ordinary Host requests. Scripted answers are fixtures only. Actual access still requires a human decision for a concrete application/window after review and exact-head CI; the current live worker target remains unset.
