# Local Host candidate — not a published DSH release

Base: the actual published npm package set `0.2.2-alpha.2`. Intended candidate identity: `0.2.2-alpha.2.codex-cua-local.1`. This directory contains public-source diffs and synthetic tests only. No native binary, device configuration, account data or credentials is committed. No upstream PR or release is authorized by this work.

`manifest.json` records original npm integrity, exact before/after file hashes and patch hashes. Patches apply to the corresponding unpacked package with `patch -p1 --fuzz=0`. The original published installation is retained separately. A local candidate must carry its own version and source identity; it must never be described as the unmodified npm release.

The route extension runs `agent/route-request` before choosing tools and assembling the prompt. Its complete configuration is captured for the request. The existing `agent/request` invariant still prohibits later route changes. A quota-recovery listener can explicitly request `reprepare:true`: the same failed step rebuilds its route/tool/prompt world without submitting the original input again. Ordinary retries keep their existing prepared world. Codex Connect selects this extension only when the Host exports `REQUEST_ROUTE_VERSION=1`; older Hosts retain the old route waterfall.

The CUA extension is opt-in (`strictWindowScope`, default false). Strict observations exclude application-global/menu roots, require live per-element target-window equality, and stamp the snapshot with the strict policy. Indexed actions resolve that stored policy and check live ownership before dispatch. Public results preserve the strict-window attestation. Ordinary application-scoped CUA behavior retains its default. These are local source changes pending installed-Host and independent review, not proof of native acceptance.
