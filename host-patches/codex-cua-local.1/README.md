# Local Host candidate — not a published DSH release

Base: the actual published npm package set `0.2.2-alpha.2`. Intended candidate identity: `0.2.2-alpha.2.codex-cua-local.1`. This directory contains public-source diffs and synthetic tests only. No native binary, device configuration, account data or credentials is committed. No upstream PR or release is authorized by this work.

`manifest.json` records original npm integrity, exact before/after file hashes and patch hashes. The builder checks these identities around applying zero-context diffs with `patch -p1 --fuzz=0`. The original published installation is retained separately. A local candidate must carry its own version and source identity; it must never be described as the unmodified npm release.

The route extension runs `agent/route-request` before choosing tools and assembling the prompt. Its complete configuration is captured for the request. The existing `agent/request` invariant still prohibits later route changes. A quota-recovery listener can explicitly request `reprepare:true`: the same failed step rebuilds its route/tool/prompt world without submitting the original input again. Ordinary retries keep their existing prepared world. The live AgentRegistry advertises `requestRoutingVersion=1`; Codex Connect uses that live service rather than an independently installed older SDK copy's exports. Older Hosts retain the old route waterfall.

The CUA extension is opt-in (`strictWindowScope`, default false). Strict observations exclude application-global/menu roots, require live per-element target-window equality, and stamp the snapshot with the strict policy. Indexed actions resolve that stored policy and check live ownership again at mutation, including delayed AXRaise. Public results preserve the strict-window attestation in every bundled state parser. Ordinary application-scoped CUA behavior retains its default. These are local source changes pending installed-Host and independent review, not proof of native acceptance.

At this checkpoint, JS syntax, old-Host Reserve tests (21) and typecheck passed. The patched native target compiled using Swift 6.4 directly; SwiftPM's manifest step failed on this machine's PackageDescription API/linker mismatch. Its zero-dependency target was compiled in Swift 6 mode without launching the helper. `WindowScopeFixture.swift` passed against the production pure policy with synthetic IDs, covering menus, foreign/unknown owners, reparenting and legitimate form/button owners. This is not an actual AX/GUI test. New-Host Reserve behavior, native source integration and the final candidate installation remain under validation. No daily service was modified.

`prepare-local-host.mjs` reproduces the candidate in a new output directory from an isolated published closure, checks source/patch hashes, rewrites all DSH package metadata and internal requirements to the distinct local version, and optionally compiles the macOS arm64 helper. Its runtime manifest pins both npm and pnpm overrides to the local package directories. It never installs into a daily profile or launches a native helper. `build-evidence.json` records the current native build hash and explicitly incomplete integration evidence. `route.test.mjs` is a scripted real-Host regression, not a model or GUI acceptance test.
