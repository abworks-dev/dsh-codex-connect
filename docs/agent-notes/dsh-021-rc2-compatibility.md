Issue [#351](https://github.com/franksong2702/dsh-codex-connect/issues/351) records two stock next-canary installation failures at main `15e92d55fd9d65971dbbd77fbd633f00b66d9353`, run `39109206040`. A new exact-rc.2 policy regression failed before the declaration update.

## Official upstream review

The complete Git trees were compared, rather than relying on the compare API's 300-file limit (the actual diff contains 456 paths):

- [rc.1](https://github.com/deepseek-ai/deepseek-harness/tree/1600d8a1e140dcde43a1a0941940a0480712c011), tag `dsh-v0.2.1-rc.1`.
- [rc.2](https://github.com/deepseek-ai/deepseek-harness/tree/687f282e8625c6b8d11ff58211a90524be2e4317), tag `dsh-v0.2.1-rc.2`.

The CLI's non-DSH dependency ranges, engine/bin/export fields are unchanged; DSH dependencies move as one exact package set. Desktop source changes only its package version. The LLM, HTTP/Connection, agent/session, compaction and consumed plugin-settings/layout/chat interfaces have no non-manifest source differences in these tags. This source comparison is not physical Desktop acceptance.

The new DeepSeek model label occupies `conversation.input.model.label`, which Codex Connect does not replace; it marks only recognized DeepSeek provider/model identities. Base composition adds the opt-in DeepSeek Search/Fetch API provider. The important shared change is [WebRuntime's rc.2 implementation](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/web/web/src/index.ts): `searchProviderId` disappears and each operation reads a Host-owned readonly `Volatile` reference. Provider registration, request/result types and source-limit enforcement remain.

## Concrete Search repair

A declaration-only candidate could install but failed the new actual-Host Search contract: the original adapter could not select Codex and the request returned the fallback provider instead. Thus this change is not a version-range-only admission patch.

The old field-based adapter is retained for existing hosts. The rc.2 branch validates the exact live-reference shape and temporarily supplies a config view for route selection. It does not write the readonly reference, its internal writer symbol, persistent Host settings or fetch selection. The Host continues updating the original reference. The adapter subscribes to the actual WebRuntime owner fiber's `loader/volatile-update` event. [Loader commits references before synchronously emitting their changed paths](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/vendor/loader/src/config/entry.ts#L158-L197). The first committed search selection change permanently yields this activation to the Host, including A → B → A and unset → B → unset entirely between searches. Comparing current values is insufficient and no revision is inferred from them. The listener is removed on disposal or installation failure. Disposal restores the original config object only while the adapter still owns the view; a replacement by another owner is retained. Unknown, frozen or malformed shapes fail before mutation. Native WebRuntime still performs provider lookup and source-limit enforcement.

Unit regressions cover both ownership shapes, idempotent disposal, later choices, replacement ownership and fail-closed validation. The installed checker enables/reloads/disables the actual packed plugin through each exact Host's WebRuntime with synthetic OAuth and intercepted Search responses. It checks native source limits, untouched fetch routing and restoration. For volatile hosts, the fixture mounts the actual WebRuntime through its exact Host Loader and submits validated changes through `Entry.update()`. Four cases cover A → B → A and unset → B → unset, each with or without a search between the changes. The same Host fiber remains active, no query dispatches to Codex after Host takeover, and an unset ambiguous route preserves the Host's refusal rather than choosing a provider. The fixture does not manually emit change events or mutate reference internals. It does not prove the Desktop settings UI.

## Scope and evidence

The candidate adds only exact `0.2.1-rc.2` to the 19 mandatory DSH peers, optional commands peer, packaged contract, shared browser/Host policy and validation gates, retaining the ten previous hosts. Mixed packages, missing metadata, rc.3/stable and a different plugin-owned pi-ai remain unverified. Node support, development SDK, runtime dependencies, default-off features, model defaults and Task pause are unchanged.

Initial candidate local Node 24.19.0 complete check passed: 151 files / 2,035 tests, lint, types, build, compatibility and package checks. Chromium passed 13 files / 67 tests. Stock exact rc.2 installed successfully, retained all default-off flags and passed doctor/profile/runtime checks, including the Search lifecycle with two reload cycles, source limits, untouched fetch routing, restoration and a later live Host choice. The legacy field-based installed Search fixture also passed. An initial sandboxed full-check retry could not bind synthetic loopback servers; the same complete check passed with loopback permission. The rc.2 fixture originally compared two Cordis tracing proxies by identity; that invalid assertion was removed while retaining captured-runtime functional checks. Independent review found the initial value-equality ownership defect. Four added round-trip unit cases fail on that candidate and pass with the owner event subscription. The revised local full check passed 151 files / 2,039 tests, lint, types, build and package checks. Stock rc.2 installation/runtime exited 0: all four real Loader round-trip cases passed, including updates entirely between searches and unset ambiguity, with no Codex dispatch after Host takeover. The revised actual-Loader legacy Search fixture also passed. Fresh PR CI installation/retained Phase 1/2 matrices for all eleven exact hosts on Node 22/24 remain required before delivery. Tests use temporary homes, synthetic credentials and intercepted provider calls. No real OAuth/model/image, physical Windows/Desktop, native #327 keyring/migration, release, deployment or daily-service acceptance is implied.

Published `0.2.0-alpha.5` does **not** contain this repair or rc.2 declaration. Its public verified-host record and installation commands stay unchanged. The source retains that development version label; modified candidate archive bytes are not the immutable npm archive. No release is performed by this PR.
