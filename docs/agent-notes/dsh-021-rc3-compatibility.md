# DSH 0.2.1-rc.3 compatibility candidate

Issue [#388](https://github.com/franksong2702/dsh-codex-connect/issues/388) records two stock next-canary rejections at main `3e71ee306e1bf6131d69d38ee53049717cb18147`, run [39923818550](https://github.com/franksong2702/dsh-codex-connect/actions/runs/39923818550). The unchanged local source archive also fails the exact rc.3 Host's plugin gate: its requirements end at rc.2. The maintainer explicitly admitted only exact rc.3 on 2026-10-23, retaining the eleven previous hosts and normal review/release gates.

## Published artifact review

The complete published DSH dependency/peer closures were compared: 295 rc.2 packages and 296 rc.3 packages, all 591 npm archives checked against registry SHA-512 integrity and SHA-1 shasums. The rc.3 CLI archive is [the exact npm artifact](https://registry.npmjs.org/@deepseek-ai/dsh/-/dsh-0.2.1-rc.3.tgz); registry identities and archive bytes, rather than an assumed Git tag, bound this comparison.

The official rc.2 tag resolves `687f282e8625c6b8d11ff58211a90524be2e4317`. The rc.3 tag returns 404. Registry manifests omit gitHead; published client-modules bundles claim short release commits `332895e` and `be72761`, neither resolvable through the public GitHub commit endpoint. No verified Git-source mapping or physical Desktop comparison is asserted.

Twenty packages have non-manifest/non-version-text changes. Composer adds new-session/preset context, an optional draft policy retaining the old clearPreviousDraft behavior, View pin/More menus and analytics. The `conversation.input.right` slot consumed here remains; this plugin does not construct the extended submission context or call draft initialization/startSession APIs. Session Controller's inspected declaration change is documentation; remotes adds analytics schema fields. Web composition adds entry-customization, and the native DeepSeek listing/account implementation changes. Codex's consumed WebRuntime, LLM/PiAI, agent/session, plugin-manager, Host webserver and primitive/layout/chat implementations have no non-version changes. Source comparison alone is not provider coexistence or runtime acceptance.

## Actual-Host investigation and scope

The baseline main-source archive SHA-256 is `2a5d5cbc56126c437313d7c9d85bb8285673f3d4701b7b73d4242842e0edae00`. It is rejected by the unmodified rc.3 installer. A separate, untracked declaration-only experiment produced `acf9c792780ec2b913825b8f4a48744ca5e64345c2c894ed50081ee82ddd6e39` under the old development version label; neither archive is the immutable published plugin.

That experiment passed normal stock add, unchanged model/Web defaults, disabled optional flags, profile composition, doctor, eleven model resolutions/preparations and disposal on Node 24.13.0. The existing installed-runtime checker exercised actual WebRuntime through its actual Loader: four Entry.update round trips, including changes entirely between searches and unset ambiguity, source limits, untouched Fetch routing, restoration and no Codex dispatch after Host takeover. Existing synthetic metrics, paused Task HTTP, preflight, retry, reserve, images and ten-process native-compaction regression fixtures also passed. No functional runtime adaptation was demonstrated necessary.

The implementation therefore adds only exact `0.2.1-rc.3` to the 19 mandatory DSH peers, optional commands peer, packaged contract, shared browser/Host policy and validation gates. The baseline, eleven old hosts, plugin-owned pi-ai `0.85.1`, Node range, development SDK, runtime dependencies, defaults and Task pause remain. Regressions retain mixed/missing-peer, future-rc/stable and pi-ai mismatch refusals. Candidate version `0.2.0-alpha.10` is prepared for the existing Alpha workflow; the published Alpha 9 pairing remains the installation recommendation until publication readback.

## Validation record

Local Alpha 10 validation on Node 24.13.0 passed the frozen dependency install, full `pnpm run check` (171 files, 2,352 passed and two skipped), and Chromium browser suite (14 files, 97 passed). The full check includes workflow/security contract fixtures, lint, typecheck, unit/integration tests, build, isolated imports, offline CLI/redaction, request metrics, compatibility and the 71-file package inventory. An upstream SDK's absent source map emits a warning during tests; it is not a failing test.

All twelve declared exact Hosts passed the unmodified isolated-install/runtime matrix with npm 10.9.3 and one identical Alpha 10 archive, SHA-256 `2650a9a0ebf91a700dc9f44b1532c5fd8e9b8b907456a9c3a931031ceb25f0a1`. The rc.3 actual-Loader Search contract includes four Host round trips, between-search updates, unset selection, source limits and Fetch/restoration checks. These installed-Host fixtures use default settings; they do not explicitly opt into the optional quota tool. Subsequent [PR CI](https://github.com/franksong2702/dsh-codex-connect/actions/runs/39937668396) at `06b6f9e2d37a7f06c122b88502425bb5c1f99d0c` and [release-main CI](https://github.com/franksong2702/dsh-codex-connect/actions/runs/39939916049) at `ab491482a8d9a44d1f5b6bc2b81229459d7ea2f5` both passed on Node 22.19.0 and 24.21.0 with all twelve stock Hosts and that same archive, plus the preserved recovery/crash, model-selection, browser, Windows and security gates. These are new exact-head results, rather than inferred Node 22 acceptance from local Node 24.

The declaration regression first failed against unchanged main (three failures). The first complete candidate check had 2,350 passing tests and two stale version expectations: the offline CLI snapshot header and the newly extended verified-pair catalog assertion. Updating only those expected versions produced the full passing result above, preserving credential-redaction, unknown/mixed/future refusal and historical-pair assertions. The prior stock rejection and investigation failures remain evidence, not passing results.

The initial archive-comparison script mishandled a removed file and was corrected using cached verified archives. Local npm 11.6.2 fixture preparation returned ERESOLVE; the repository CI's pinned npm 10.9.3 installed all 296 rc.3 roots with normal peer checks, no force/legacy flags and empty task npm configs. The peer-tree report retains two extraneous optional WASM entries, no invalid peer version. These are fixture/installer observations, not a proven Host defect. The original checker summary obscured the rejection behind stdout; a separate full capture confirmed the actual gate.

All results are keyless fixtures and published-package comparisons. They do not establish real OAuth/model/settings user acceptance, native Desktop/iPhone, Safari, keyring migration or OS text zoom.
