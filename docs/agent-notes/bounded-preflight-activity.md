# Plugin-owned bili preflight timing

[#340](https://github.com/franksong2702/dsh-codex-connect/issues/340) reports continuous bili compression heartbeats followed by the Host's ordinary idle timeout. Existing plugin-only adaptations provide the relevant ownership precedent: [#294](https://github.com/franksong2702/dsh-codex-connect/pull/294) translates Host/provider context, [#262](https://github.com/franksong2702/dsh-codex-connect/pull/262) scopes the proxy Fetch implementation, and [#302](https://github.com/franksong2702/dsh-codex-connect/pull/302) uses a public tool-result hook. None alone proves a timeout adaptation works.

The adapter uses the public explicit-key provider callback as its post-preparation activation point. An iterator-local AsyncLocalStorage scope connects that callback, the acquired proxy route and response-byte observation. The public profile's finite `300000 + B` idle interval prevents an inner Host timer from expiring before the plugin's nonrenewable preflight budget; a separate plugin watchdog preserves ordinary 300000ms idle behavior. `B` is startup-validated and capped to prevent Node timer overflow. `dsh-timeout` is an explicit, exact-version peer; the SDK, pi-ai pin, supported Host versions and feature defaults are unchanged.

The timing wrapper is outside native-compaction cleanup but inside request diagnostics and metrics. Its own timeout is fixed before abort, caller cancellation can drain already-produced Host terminal chunks, and an uncooperative inner return is detached rather than awaited. Recognition stops on data or oversized frames without ending the budget; only a converted Host result, EOF or cleanup ends preflight timing. The [operator reference](../preflight-activity.md) owns configuration and verification limits. No upstream patch, fork, release, service change or real-account acceptance is implied.
