# Explicit conversation Ultrafast — 2026-10-19

This source change addresses #342. Standard omits the speed hint; legacy Fast sends `priority`; an explicit Ultrafast choice sends `ultrafast` only on exact provider `openai-codex` and exact models `gpt-6-astra` / `gpt-6.1-sol`. Neither effort nor model/output settings change. New-session/subagent Fast defaults retain their existing behavior and cannot seed Ultrafast. Auxiliary compaction/title calls do not inherit it.

This conversation-only scope does not implement the issue's proposed Ultrafast session/subagent default settings. Finite SSE remains the supported policy; there is no WebSocket transport change or measured latency-gain claim in this PR. Those proposals are not delivered by the selector.

The existing bounded process-local Fast registry remains the compatibility surface. A separate bounded control map adds account-key, plugin-instance, live-session incarnation and model-selection revision binding. The Host's global `session/event` feed observes only future `model/selection` metadata; no prompt/history scan or persistence is added. Missing live lookup fails closed. Login/logout/account commands invalidate control generations without changing saved Fast preferences. Normal captured-account auth resolves the bearer; only the existing opaque account hash enters request-local AsyncLocalStorage and is cleared at stream termination. Pending requests cannot acquire a later account's paid choice.

The same-origin Connection-authorized enum route validates bounded strict input and compare-and-set generation/revision. Old POSTs are rejected rather than replayed. Generation-scoped model-change invalidation cannot clear a replacement generation. A boolean Fast write explicitly replaces Ultrafast; its GET returns 409 for a current Ultrafast choice, preserving honest legacy readback. The final payload projection runs after a previous callback's replacement and rejects model mismatch. Expiry stays sticky across Host retries until a fresh explicit control read/choice.

Model support is separate from billing entitlement. Eligibility remains unknown; there is no remote discovery, plan inference, OAuth scope change, SIWC token reuse, private endpoint or paid probe. Cached/built-in `model/list` absence is not a denial. The pi-ai response callback exposes only HTTP status/headers, so this implementation deliberately retains **unverified served tier**, including after HTTP200 or a completed response. It adds no SSE body observer or entitlement cache. It must never claim account eligibility, actual billing, latency improvement or accepted Ultrafast from a request hint. Existing provider/Host retries are not disabled or extended; the feature adds no generation replay or silent tier fallback.

Offline validation covers exact-model payloads, real pi-ai SSE transport with synthetic credentials, account/auth races, Host model-selection away/back, stale mutation/eviction, strict HTTP admission, legacy Fast commands/defaults, auxiliary exclusion and Chromium controls in both languages. Synthetic successful responses prove transport and local UI only. Real OAuth served tier, account qualification, billing and latency remain untested. No package publication or daily service update is included.
