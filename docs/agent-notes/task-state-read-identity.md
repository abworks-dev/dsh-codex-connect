# Task state read identity

Refs #329. `AtomicTaskDocumentStore.read()` previously trusted the opened handle without comparing it to a leaf observed before open. A real same-content replacement could be accepted, and disappearance before opening could be converted into `undefined`, letting an update callback replace state instead of failing closed.

The reader now binds a private regular single-link leaf to its opened handle using native bigint device/inode and metadata before/after bounded reads and after close. It also rechecks the private parent directory's identity after close. Only initial missing-directory/leaf observations return `undefined`; later ENOENT rejects as `TASK_STATE_UNSAFE` before decoding or invoking an update callback. A pre-existing symlink now reports `TASK_STATE_UNSAFE` consistently with other unsafe leaves. Other I/O/decoding failures remain unavailable, and codec errors retain their typed failures. Formats, codecs, permissions, write/lock behavior and Task activation do not change.

The original real-filesystem regression had three failures (same-content replacement, observed disappearance, update fallback after disappearance) and one ordinary-read positive control. Native tests use actual files, symlinks/hardlinks and FileHandles; wrappers only schedule mutations or constrain partial reads, never substitute filesystem contents. Tests cover open/read/close boundaries, partial multibyte reads, metadata/link/directory replacement, initial absence and handle cleanup. Windows CI runs this file directly; private POSIX 0400 read coverage is platform-specific. Actual link creation failures fail rather than silently skip.

This is read-snapshot safety, not permanent path immutability after return. Ancestor-directory trust, write-side path/handle races, writable Windows flush access and power-loss durability are outside this repair. A failed read does not authorize a new grant. #329 remains open until its other subitems are addressed. No daily profile, real model/account, credentials, privileges, dependencies or release defaults are changed.
