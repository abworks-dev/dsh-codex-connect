# 0.2.0-alpha.4 — exact DSH alpha.2 / alpha.3 compatibility and maintenance

## Scope

This candidate adds exactly DSH `0.2.1-alpha.2` and `0.2.1-alpha.3`, preserving `0.1.7-rc.1`, `0.1.7-rc.2`, `0.2.0-rc.1`, `0.2.0-rc.2` and `0.2.1-alpha.1`. A consistent package set is required. Later prereleases, stable releases and mixed DSH package sets do not inherit verified support. Existing supported hosts do not need an upgrade.

The stock DSH compatibility gate is retained: there are no version exemptions or arbitrary future-version ranges. The image regression fixture exercises native tools and agent-scoped PTC separately instead of the retired `both` mode, with an explicit cancellable working directory. This changes the test fixture, not product defaults or a user's tool mode. Plugin-owned pi-ai remains `0.85.1` and Schemastery remains `3.18.4`; the development SDK baseline is unchanged.

Codex's fixed model catalog remains available before sign-in without capturing or refreshing an account, independently of alpha.3's credential-gated generic catalog. This is metadata discovery only: request dispatch still requires the captured OAuth account and retains its authentication failures. Settings projections also preserve alpha.3 snapshots without `mode`, while retaining the older memory-mode rejection and Host writability, revision, conflict and accepted-value checks.

This release also carries the previously merged maintenance work:

- [#331](https://github.com/franksong2702/dsh-codex-connect/pull/331): private HTTP routes require Host admission, retain Host/Origin restrictions, own their cleanup and roll back partial registration; packed-library inventory rejects stale and unexpected artifacts.
- [#332](https://github.com/franksong2702/dsh-codex-connect/pull/332): bounded and cancellable UI requests, and settings saves that do not depend on a model-catalog request completing.
- [#333](https://github.com/franksong2702/dsh-codex-connect/pull/333): targeted dependency security floors and development-lock fixes. These do not patch dependencies in a separately installed Host. The unresolved low-severity KaTeX advisory remains a separate compatibility task.
- [#335](https://github.com/franksong2702/dsh-codex-connect/pull/335): manual proxy drafts survive unrelated Host updates and release local ownership after the exact value is accepted; discard and stale-probe cancellation remain available.

## Verification and publication boundary

Release admission requires the complete check, Chromium regressions and all seven exact stock-Host installation/runtime checks against identical packed bytes. Those Host checks cover default preservation, model registration/preparation, disposal, synthetic native/PTC image operations and retained recovery contracts. Verification identities and workflow results belong in the release evidence, not assumptions from an older passing commit.

The [exact compatibility catalog](../../verified-compatibility.json) records completed pairing checks; a candidate record is not npm publication. The public installation recommendation stays on an already published pair until the new package, tag and prerelease are independently read back. Published artifacts are immutable, and publishing this Alpha does not promote `latest`.

After this exact version has been published, use the existing profile name in place of `web`:

```sh
dsh plugin --profile web add dsh-codex-connect@0.2.0-alpha.4
```

Do not bypass Host version checks or rebuild an existing profile to force installation. Desktop has a separate profile and CLI; follow the [installation guide](../../INSTALL.md#official-desktop), not a second running Desktop instance.

No new live OAuth, real-provider requests, authenticated-browser acceptance on every new Host, physical Windows/mobile or real Desktop acceptance is claimed by synthetic checks. Real Desktop validation remains deferred to an independently isolated environment. Task remains paused, optional capabilities remain off by default, and account data and Host-owned permissions are preserved. Publication does not install the candidate into a daily profile, upgrade DSH or restart an existing service.
